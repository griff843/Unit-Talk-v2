# WORK-2026092708 — pipeline health judges every recent receipt's destination

Tier: T2 · Lane type: governance · Executor: claude

Repo-owned work order (tracker independence, ratified 2026-09-05). No Linear issue exists for this identity by design.

## Objective

`scripts/pipeline-health.ts` § "Authorized delivery targets" is the monitor's containment check: did anything deliver somewhere it should not? It reads `distribution_receipts` with `.limit(100)` and no order, which on 2026-09-27 means 100 of about 3,739 receipts, chosen arbitrarily. It compares each receipt's `channel` against a hardcoded `['discord:canary', 'discord:best-bets']` plus two channel ids.

- It flags 2,145 historical `discord:#canary` receipts as non-live.
- It never names `official-picks`, the only target `human-capper` delivers to.
- Since UTV2-1929 a receipt's `channel` is the resolved Discord id, and the logical target lives in `payload.target`.

So the warning is permanent, it is sampled, and it can miss a real delivery to an unauthorized destination.

## Acceptance Criteria

- Receipts inside a bounded authority window are read completely: paged in `id` order with `readAllPages`, and checked against an exact count. A partial read is CRITICAL, never clean.
- Each receipt's logical target is `payload.target` when present, otherwise `channel`. It is classified by a pure, unit-tested function:
  - `governed` when it is in `governedDeliveryTargets` from `@unit-talk/contracts`.
  - `control` when it is the canary lane.
  - `unrecognized` otherwise.
- An `unrecognized` receipt inside the window is CRITICAL and named. Receipts older than the window are not judged.
- The hardcoded `LIVE_TARGETS` / `LIVE_CHANNEL_IDS` lists are removed from the script. The JSON report carries the window census.
- No database write, no delivery-path change, and no change to `apps/worker` (its replay allowlist is a separate, deliberate restriction).
