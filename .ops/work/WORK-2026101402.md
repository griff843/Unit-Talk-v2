## Hazards (read before coding)

- **Order of operations.** Once `deriveSportId` returns `'WNBA'`, `picks.sport_id` carries an FK to `sports(id)`. The runtime must not deploy anywhere the migration has not been applied (staging proof DB included, production). Deploy and production migration apply are Griff's separate authorizations.
- **Scoring stays unsupported.** `apps/api/src/t1-proof-utv2-1954-promotion-replay.test.ts` uses WNBA as the *unsupported-sport* (score capped at 60) fixture. Do not touch `packages/domain` scoring; WNBA must remain unsupported there. Confirm that test still passes unchanged.
- **Do not add WNBA to alert/ingest enablement** (`isAlertSportActive('WNBA')` must stay false, `alert-agent-service.test.ts:398`).
- No Discord, delivery, kill-switch, provider, or containment change. Track Only never produces delivery.
- Smart Form redesign is out of scope.

## Acceptance Criteria

- WNBA is accepted as a team sport by the server guard and mirrored by the client; `submissionGuardsMatchServerTeamSports`-style pin test still passes with both lists containing WNBA.
- A WNBA moneyline/spread/total Track Only submission with two governed participant ids passes validation and a team-sport enteredParticipants >= 2 check.
- `deriveSportId` returns `'WNBA'` for metadata sport `WNBA`/`wnba` and for `wnba-*` market keys; `'NBA'` inputs are unaffected (WNBA does not contain-match NBA).
- `GET /api/reference-data/catalog` in-memory returns 10 sports.
- The unsupported-sport scoring test and the WNBA-inactive alert test pass unchanged.
