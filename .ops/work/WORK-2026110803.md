# WORK-2026110803 — write-reconciled-sidecar: sanctioned model-routing sidecar for reconciled lanes

Tier: T1
Lane type: governance-tooling
Executor: claude

Source: PM approval 2026-11-09. PR #1839 (WORK-2026110705) was reconciled via `reconcile-routing` to the observed Claude subagent routing, but nothing in the repo writes the `model-routing.json` sidecar that `ops:proof-generate` and the pre-merge contract (`validatePreMergeModelRoutingEvidence`, `LANE_MANIFEST_SPEC.md` §15.1) require for a reconciled lane. The only writer is `codex-exec`, which would manufacture Codex execution telemetry for work Codex did not do.

## Tier rationale

T1: governance tooling that produces a required proof artifact (`DELEGATION_POLICY.md` classes governance as T1). Merge needs `t1-approved` plus a `pm-verdict/v1` APPROVED comment from CODEOWNERS bound to the exact head SHA. PT1 BLOCKED_BY_CONTAINMENT at admission is admitted under PM route B (record the deferral; staging proof bound before merge). No migration, no runtime path, no CI or proof-requirement change.

## Objective

Add `pnpm ops:lane-manifest write-reconciled-sidecar <ID>`: generate `docs/06_status/proof/<ID>/model-routing.json` for a reconciled lane only from the reconciled manifest `model_routing`, after re-verifying the original authorized PM routing comment, and validate it with `validatePreMergeModelRoutingEvidence` before writing.

## Allowed file scope

- `scripts/ops/lane-manifest.ts`
- `scripts/ops/lane-manifest.test.ts`
- `scripts/ops/model-routing.ts`
- `scripts/ops/model-routing.test.ts`
- `docs/05_operations/LANE_MANIFEST_SPEC.md`
- `.ops/work/WORK-2026110803.md`, `docs/06_status/proof/WORK-2026110803/`

Out of scope: `codex-exec.ts`, `proof-generate.ts`, `lane-close.ts`, CI workflows, `package.json` (both test files are already registered in `test:ops`), any weakening of proof or merge controls, general governance modernization.

## Acceptance Criteria

- AC1: The sidecar is built only from the manifest's reconciled `model_routing` (model, reasoning_effort, profile, policy_version, override.authorized_by, override.observation, override.declared). It carries `override_used: true`, `execution_verification: "unverified-external-session"`, top-level `unavailable_fields` equal to the manifest's, `routing_source: "reconciled-observation"`, the declared routing under `declared_routing`, and the approval identity. It contains no `codex_cli_version`, exit code, token usage, wall time, prompt bytes, `closeout_binding` or `merge_sha`.
- AC2: The original approval comment recorded in `override.approval` is re-fetched from GitHub and re-verified (CODEOWNERS non-bot author, pm-verdict/v1 APPROVED, Issue/PR/Head SHA equal to the stored approval identity, exact `Routing reconciliation:` line matching the manifest). The stored approval PR must equal the lane's `pr_url` and the stored reviewer must equal `override.authorized_by`.
- AC3: An ordinary later PR head advance does not invalidate the historical reconciliation: the stored approval head SHA must be a commit in the PR's history, not equal to the current head.
- AC4: Refused with a named error: unreconciled lane (no `override.declared`/approval), non-Codex executor, done lane, missing approval record, altered or mismatched identity, approval head SHA absent from the PR history, and an existing sidecar whose content differs. An identical existing sidecar is an idempotent no-op.
- AC5: The sidecar passes `validatePreMergeModelRoutingEvidence` with `manifestRouting` and `expectedIssueId` before any write; the write is atomic.
- AC6: Focused tests cover success, each refusal, the PR-head-advance case, idempotence, and a mutation proof (removing the history check or the identity check fails a named test).
- AC7: `LANE_MANIFEST_SPEC.md` §15.1 documents the command. Existing proof, CI and merge controls are unchanged.
