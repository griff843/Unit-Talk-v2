# WORK-2026092703 — The pipeline health monitor reads the whole outbox and classifies dead letters the way the readiness gate does

Tier: T2 · Lane type: governance · Executor: claude

Repo-owned work order (tracker independence, ratified 2026-09-05). No Linear issue exists for this identity by design.

## Objective

`scripts/pipeline-health.ts` disagrees with the readiness ledger about the same dead-letter rows. On 2026-09-27 it reported 41 true dead letters; the ledger's `dead_letter_count` reported 0 true failures among 1954 rows. Measured live the same day with the canonical rule, all 1954 are 1950 governance holds, 4 unattempted-unclassified, and 0 true failures; the monitor's old rule calls 45 of them true failures. Two defects cause this:

- **It reads half the outbox.** The non-sent read asks for `.limit(5000)`, but PostgREST caps every response at 1000 rows. Production holds 1990 non-sent rows (1954 `dead_letter`, 4 `pending`, 32 `processing`, measured 2026-09-27). The page is ordered by `updated_at desc`, so 990 dead letters are silently dropped. The pending and processing rows survive only because they are newer, not because anything guarantees it.
- **It carries its own copy of the dead-letter rule.** It treats a row as governance only when `attempt_count === 0` and `last_error` starts with one of three prefixes. The readiness gate buckets with `classifyDeadLetter` from `scripts/ops/outbox-triage.ts` via `bucketDeadLetterRows`, whose docstring names `pipeline-health.ts:80` as a divergent copy.

## Acceptance Criteria

- The non-sent outbox read pages in `id`-ordered pages of 1000 until a page comes back empty. An exact `count` of non-sent rows is read alongside it. If the rows read do not match the count, the report raises a **critical** "outbox read incomplete" and exits non-zero. It never reports a partial population as whole.
- Dead-letter rows are split with the same rule the readiness gate uses: `classifyDeadLetter(last_error)` crossed with `attempt_count > 0`, giving governance hold, unattempted-unclassified, and true failure. A non-numeric `attempt_count` counts as attempted (fail closed).
- A unit test proves parity: on the same rows, the monitor's per-bucket counts equal `bucketDeadLetterRows` from `readiness-refresh.ts`.
- True failures stay **critical**. Governance holds and unattempted-unclassified rows are **warnings**, both counted and named, and never dropped from the report. The JSON report states the three buckets.
- The paging and classification are unit-tested, including a fake that serves more than one page and a guard that fails if the `id` ordering is removed. `pnpm type-check` and `pnpm test` pass.
- No database write, no containment change, and no change to `packages/observability`, the worker, `outbox-triage.ts`, `readiness-refresh.ts`, or any delivery path.
