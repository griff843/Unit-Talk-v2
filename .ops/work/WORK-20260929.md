# WORK-20260929 — Optimize Codex usage

## Objective

Reduce Codex token and reasoning cost across Unit Talk without weakening repository safety,
verification, or production governance.

## Acceptance criteria

- Compact always-loaded repository instructions while preserving architectural, Tier C, testing,
  and PR-closeout controls.
- Select agent-brief context from lane type and file scope, with full-brief fallback on parser or
  classification uncertainty.
- Route bounded work to efficient supported models and reserve expensive reasoning for explicit
  rescue or escalation.
- Provide compact local repo briefing, focused search, and concise full-gate verification tools.
- Record prompt-size and wall-time evidence for Codex lane executions.
- Preserve compatibility with the installed GitHub CLI and verify all changed behavior with
  `node:test` tests.

## Constraints

- Do not change product runtime behavior, domain contracts, database schema, or delivery targets.
- Do not bypass `pnpm verify`, file-scope, tier, R-level, or protected staging checks.

## Verification

- Run focused agent-tooling, routing, execution-packet, executor, and lane-governance tests.
- Run `pnpm verify`; protected CI supplies staging-only credentials for the live-DB phase.
- Run the R-level compliance check against `origin/main`.
