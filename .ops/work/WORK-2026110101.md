Tier is T1 because this changes which staging rows the WORK-2026103009 reaper may delete. That reaper merged as T1 (#1813).

## Objective

The WORK-2026103009 dry run (run 41319898348, cutoff 2026-10-24T00:00:00Z) selected 113,147 picks. That count includes 9,009 picks whose `status` is `settled` but which have no `settlement_records` row. The reaper's only settlement test is the presence of a `settlement_records` row, so it treated them as unsettled fixtures.

Option B keeps every pick whose `status` is `settled`, whatever its settlement rows say.

## Acceptance Criteria

- `selectReapablePicks` skips a row whose `status` is `settled`, counted under a new skip reason `status_settled`. It is evaluated after the existing checks, so the count is exactly the picks this correction removes from eligibility.
- Every execute-mode pick DELETE re-asserts `status <> 'settled'` (`picks.status` is NOT NULL), so a pick that becomes settled between selection and delete is left alone.
- Unit tests in `scripts/ci/staging-path-enforcement.test.ts` cover:
  - the new skip;
  - the delete-time filter, through the existing in-memory store.

  A mutation check shows the tests fail without each change.
- After merge, a fresh read-only dry run of `staging-fixture-reap.yml` at the same cutoff reports before and after eligibility counts. No execute is dispatched; execute needs Griff's separate approval.
