## Objective

The staging project `xskgrzbteyqdufktjrjx` is CI-only; its oldest pick is from 2026-07-30, when the project was created. Nothing removes what CI writes to it.

- `picks` holds 184.5k rows, and CI adds 1k–4.5k a day.
- Service-role scans that filter `picks` by status, order by `created_at` and paginate by offset come close to the 8 s statement timeout.
- Staging proofs therefore fail with 57014 statement timeouts and 502s, and each failure costs a full `ci.yml` rerun on a shared staging slot.

As read on 2026-10-30, 172k picks are older than 7 days. Of those, 113k have no `settlement_records` row and no `pick_reviews` row.

This lane adds a reaper for exactly those picks. It deletes them, their `ON DELETE CASCADE` children (`distribution_outbox` and through it `distribution_receipts`, `pick_lifecycle`, `pick_offer_snapshots`, `pick_promotion_history`), and the submissions that are left with no picks and are older than the same cutoff (`submission_events` cascade).

## Acceptance Criteria

- **`scripts/ci/staging-fixture-reap.ts`:**
  - Refuses any target that is not the approved staging project, before it constructs a client. It obtains the client from `@unit-talk/db/privileged-client-boundary`.
  - Runs a dry run by default. A dry run writes nothing and reports selected picks by status and by source, excluded picks (settled, reviewed), and the orphaned submissions it would delete.
  - Deletes only in execute mode, which requires an explicit `--execute`, a fixed `--cutoff` and a `--max-picks` cap.
  - Refuses a cutoff younger than 7 days.
  - Completes the whole selection, read-only, before deleting anything, and refuses without deleting if the selection exceeds `--max-picks`.
  - Deletes in bounded batches. Every delete statement re-asserts `created_at < cutoff`.
  - Never deletes a pick that has a `settlement_records` row or a `pick_reviews` row. A pick that gains one between selection and delete is re-checked per batch and left alone.
  - Never touches `settlement_records` or `pick_reviews`.
  - Pages by primary key, never by offset.
- **Pure selection logic is unit-tested in `scripts/ci/staging-path-enforcement.test.ts`**, where the board-drain tests already live. The tests cover the age margin, the settled and reviewed exclusions, the minimum-cutoff refusal and the max-picks refusal. The reaper's CLI entrypoint is added to that file's real-path entrypoint guard list.
- **`.github/workflows/staging-fixture-reap.yml`:**
  - Is `workflow_dispatch` only and binds the `staging-ci` environment.
  - Defaults to dry-run.
  - Requires `cutoff` and `max_picks` inputs for execute.
  - Uploads the JSON report as an artifact and writes it to the step summary.
  - Does not join the `staging-ci-db` concurrency group, so it can never cancel a pending PR proof. It uses its own non-cancelling group.
- **Order of operations:** the dry-run counts go into this PR for Griff's T1 review. Execute is dispatched only after merge, with the reviewed cutoff and cap.
