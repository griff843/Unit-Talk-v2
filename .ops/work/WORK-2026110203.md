# WORK-2026110203 — codex-exec records observed model routing from the Codex rollout

Tier: T2
Lane type: governance
Executor: claude

Source: Griff, "OPERATING-MODEL CLAUDE — ADOPT HYBRID CODEX EXECUTION", 2026-11-02:
- "The wrapper records truthful model-routing and available execution telemetry."
- "Missing telemetry fails honestly rather than generating a fabricated value."

Tier is T2. The change adds an observation block and a mismatch check to the Codex wrapper. It does not change:
- any approval artifact, merge authority, branch protection or production authorization;
- the routing fields the closeout binds (`model_profile`, `model`, `reasoning_effort`, `override_*`).

## Objective

`scripts/ops/codex-exec.ts` writes `docs/06_status/proof/<ID>/model-routing.json` from the manifest's declared routing. It never checks what Codex actually ran. The Codex CLI already records the truth: each `codex exec` run writes a rollout file under `$CODEX_HOME/sessions/` (default `~/.codex/sessions/`). That file holds:
- a `session_meta` record: `id`, `cwd`, `originator`, `cli_version`;
- one `turn_context` record per turn: `model`, `effort`;
- `token_count` events.

After Codex returns, the wrapper should read that rollout and record what it observed next to what was declared.

## Acceptance Criteria

- **Finding the rollout.** After the child exits, the wrapper looks for rollout files that meet all three conditions:
  - `session_meta.cwd` equals the lane worktree;
  - `originator` is `codex_exec`;
  - the session timestamp falls within the attempt's start and end.
- **Exactly one match.** `model-routing.json` gains an `observation` block:
  - `status: "observed"`;
  - `session_id`, `model`, `reasoning_effort`, `cli_version`;
  - `turns`, and `total_tokens` taken from the last token count.
- **No match, several matches, or an unreadable file.** `status` is `"unavailable"` with a `reason`. Every observed value is `null`, and its name is listed in `unavailable_fields`. No declared value is copied into an observed field.
- **A field missing from the rollout.** That field alone is `null` and listed in `unavailable_fields`.
- **Observed differs from declared.**
  - Covers the model, or any turn's effort.
  - `observation.status` is `"mismatch"`.
  - The wrapper fails closed with code `ROUTING_MISMATCH` and does not report `SUCCESS`.
  - The evidence file is still written and persisted, so the mismatch is on record.
- **Existing fields keep their meaning.** The declared top-level fields are unchanged, and a new `routing_source: "declared"` field labels them as declared values.
- **Unavailable is not a failure.** An unavailable observation does not fail the run, but the run's JSON result carries `observation_status`, so the orchestrator sees it.
- **The JSON result reports the PR.** On `SUCCESS` it also includes `pr`:
  - `{ number, head_sha, head_matches_local }` from `gh pr view <branch>`;
  - `null` with a reason when there is no PR or `gh` is unavailable.
  - Nothing is posted. Executor-result publication stays an orchestrator step, because for T2 it is an approval artifact.
- **Tests and checks.**
  - Unit tests in `scripts/ops/codex-exec.test.ts` cover the observed, unavailable (none and ambiguous), partial-field and mismatch cases, using temporary rollout fixtures.
  - A mutation check shows each test fails without its change.
  - The existing CEP-conformant sidecar tests in `truth-check-lib.test.ts` still pass.
