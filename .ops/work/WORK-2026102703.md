## Objective

Production Command Center is configured with only a bearer token and no `COMMAND_CENTER_OPERATOR_IDENTITY`, so every authenticated action is attributed to the default actor `command-center`, and a browser has no credential it can present. Settlement attribution comes from the middleware-issued actor (`settle.ts` sends `settledBy: operatorActor`), so fixing the actor fixes attribution.

1. When HTTP Basic credentials authenticate a request and no explicit `COMMAND_CENTER_OPERATOR_IDENTITY` is configured, the actor is the authenticated username, but only when it is already a canonical id (`^[a-z0-9][a-z0-9_-]*$`). A username that is not canonical keeps the existing configured/default identity; it is never rewritten.
2. Bearer-token authentication is unchanged: it keeps the configured or default identity, so the machine token is not attributed to a human operator.
3. Browser sessions minted from Basic credentials verify against the identity those credentials produce, so a session cannot claim any other actor.

## Acceptance Criteria

- Basic auth with username `griff843` and no explicit identity yields actor `griff843`; bearer auth on the same configuration yields `command-center`.
- An explicit `COMMAND_CENTER_OPERATOR_IDENTITY` still wins for Basic auth (existing behaviour and tests unchanged).
- A non-canonical Basic username never becomes the actor.
- A session minted from Basic credentials authenticates as that actor; a forged or remapped actor is refused.
- Wrong credentials and missing credentials are still refused.

## Guardrails

- Command Center stays internal-only (127.0.0.1 port, SSH tunnel). No Caddy route, no public hostname, no deploy workflow change.
- No credential value in code, tests, logs or chat. Griff sets `COMMAND_CENTER_AUTH_USERNAME` and `COMMAND_CENTER_AUTH_PASSWORD` himself.
- No API, settlement-logic or schema change.
