## Objective

Remove every Linear dependency from scripts, workflows, hooks, skills, agents and canonical docs, so lanes run from repo work orders (`.ops/work/WORK-<n>.md`) alone, without weakening any merge gate.

## Acceptance Criteria

- No script, workflow, hook, skill or agent reads or writes Linear, and no Linear credential is read anywhere (`LINEAR_API_TOKEN`, `LINEAR_API_KEY`, `LINEAR_TEAM_ID` removed from `AppEnv`, `.env.example` and workflows).
- `linear-auto-close.yml`, `queue-grooming.yml`, `scripts/linear-workflow.ts`, `scripts/ops/linear-client.ts` and the Linear hooks are deleted.
- `ops:preflight` and `ops:lane-start` take work identity, tier, lane type and acceptance criteria from the committed work order; a missing work order is a refusal, not a tracker fetch.
- `ops:truth-check` makes no tracker call: L1–L4 are retired; L5 (`t1-approved` on T1) still runs; C1 and C7 always evaluate from the manifest and GitHub.
- `ops:lane-close` and `ops:lane-finalize` perform no tracker write; `ops:lane-finalize` still applies the PR tier label.
- Dispatch candidates (`ops:digest`, `codex:classify`, `codex:dispatch`, `ops:brief`) come from open work orders.
- Alerts that used to file Linear issues go to GitHub issues.
- `merge-gate.yml` merge-authority logic is unchanged (comments only).
- `pnpm lint`, `pnpm type-check` and `pnpm test` exit 0, with no new failure against `main`.

## Guardrails

- No change to merge authority, the merge gate's decision logic, CODEOWNERS or branch protection.
- No production DDL: the `p_linear_issue` column in `database.types.ts` and the `utv2-539` scripts stay.
