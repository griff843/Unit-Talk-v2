# WORK-2026112501 — Command Center public URL behind Google sign-in on the production host

Tier: T2 · Lane type: runtime · Executor: claude

Repo-owned work order (tracker independence, ratified 2026-09-05). No Linear issue exists for this identity by design.

## Authority

- Griff, 2026-11-25, project thread decision card "Give Command Center a public URL behind Google sign-in, reversing the internal-only rule?" → chose "Public URL + Google sign-in". This supersedes PM decision 7 (2026-09-24, internal-only) for the Command Center.
- Motivation: manual settlement of Smart Form picks needs the Command Center; today it is reachable only through `pnpm ops:cc-bridge`, which needs the production SSH key on the operator's machine.

## Objective

Give the production Command Center a public, TLS-terminated hostname on the existing Hetzner host, where every request first passes a Google sign-in gate limited to an operator allow-list, and the Command Center's own operator sign-in still applies. Default-off; enabled by repository configuration and a deploy.

## Acceptance Criteria

- `deploy/production/command-center.caddy`: a site where `forward_auth` to the gate precedes the single `reverse_proxy command-center:4300`, with no bypass path.
- `command-center-auth` compose service (oauth2-proxy, Google provider, email allow-list) behind its own profile `command-center-public`, with no host port.
- `deploy/production/command-center-edge.sh` is the single writer/remover of the gate env, allow-list and site file, called from canary and promote; it fails closed on missing values, a non-hostname domain, an empty or malformed allow-list, or a public edge without an enabled Command Center.
- The deploy selects the profile only when both variables are `true`, validates that the gate resolves, reloads Caddy, and fails unless an unauthenticated `GET /picks` on the hostname redirects to `/oauth2/start`.
- Rollback restores or removes the gate configuration from the target release's snapshot.
- Tests: `scripts/ci/command-center-edge.test.ts`, updated `scripts/ci/nextjs-deploy-wiring.test.ts`.
