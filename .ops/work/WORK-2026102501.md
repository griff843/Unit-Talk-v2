## Objective

Manual player-prop submission in Smart Form must resolve a canonical market key for every catalog stat type the UI offers, and must resolve it per sport. Today `resolveSubmissionMarketKey` (`apps/smart-form/lib/form-utils.ts`) throws "Cannot resolve canonical market key" for catalog stat types missing from `STAT_TYPE_TO_SUBMISSION_MARKET_KEY` (NHL Goals Against, Plus/Minus, Save Percentage; NBA Field Goals Made, Free Throws Made, Minutes Played, Plus/Minus; MLB Runs; NFL Sacks), so nothing persists. The map is also keyed by stat name only, so NHL "Points"/"Assists" resolve to NBA keys and persist as `player_points_ou` instead of `player_hockey_points_ou`.

## Acceptance Criteria

- Every production `stat_types` row for NHL, NBA, MLB and NFL resolves a market key without throwing, using market ids production already uses.
- Lookup is sport-aware: NHL Points/Assists resolve to hockey keys, NBA Points/Assists to NBA keys.
- A stat type with no mapping is refused explicitly (and visibly at selection time, not at submit); there is no silent fallback to a different market.
- Unit tests in `apps/smart-form/test/form-utils.test.ts` cover the above, including a negative case.
- A row-asserted e2e case in `apps/smart-form/e2e/phase-one.spec.ts` covers an NHL Shots on Goal player prop (201, persisted row, empty distribution_outbox, Track Only); it is gated by `UNIT_TALK_SMART_FORM_E2E=1`.
- No staging or production write, migration, deploy, delivery, kill-switch or Whop change.
