# WORK-2026092705 — runtime:health judges the whole outbox with the canonical dead-letter rule

Tier: T2 · Lane type: governance · Executor: claude

Repo-owned work order (tracker independence, ratified 2026-09-05). No Linear issue exists for this identity by design.

## Objective

`scripts/runtime-health.ts` (`pnpm runtime:health`, and `pnpm ops:runtime-health` through `canonical-health.ts`) computes Queue Movement from a single unfiltered, unordered read of `distribution_outbox`. On 2026-09-27 production holds 5750 rows: 3760 `sent`, 1954 `dead_letter`, 32 `processing` and 4 `pending`. PostgREST returns at most 1000 of them, in no defined order. The report's pending, stuck and dead-letter counts are therefore a sample, and it can miss every pending row. It also keeps a third local copy of the dead-letter rule, which diverges from the readiness gate's `bucketDeadLetterRows`.

## Acceptance Criteria

- Non-sent rows are read with the id-ordered paged reader from `scripts/ops/pipeline-health-classification.ts`, and compared against an exact count. A partial read makes Queue Movement `UNKNOWN`, never `HEALTHY`.
- `sent` rows are counted with an exact count, not fetched.
- Dead letters are bucketed with `partitionDeadLetters` (the canonical rule). True failures are `FAILED`. Governance holds and unattempted-unclassified rows are `DEGRADED`, with counts named.
- Pure queue-state evaluation is extracted and unit-tested, including a partial-read test and a parity test with the readiness gate.
- No database write, containment change, or change to delivery paths.
