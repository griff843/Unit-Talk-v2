# WORK-2026092622 — A repo-owned WORK identity is admitted without Linear

Tier: T2 · Lane type: governance · Executor: claude

Repo-owned work order (tracker independence, ratified 2026-09-05). No Linear issue exists for this identity by design.

## Objective

Codex's governed admission of WORK-2026092606 stopped on two non-waivable preflight checks:

- **PL1** `Linear issue not found: WORK-2026092606`. When a Linear credential is present, `runLinearChecks` sends every identity to Linear, including a repo-minted `WORK-###` that no tracker issue can ever match. The only Linear-free path was "no tracker credential", which an executor with a credential cannot take.
- **PG2** `working tree is not clean`. Ten work orders under `.ops/work/` sat untracked in the root checkout, because their lanes never committed them.

Make a valid repo-owned `WORK-###` contract admissible without Linear, whatever the executor's credentials. Give the ten work orders their correct repository disposition. Weaken no other safeguard.

## Acceptance Criteria

- A `WORK-###` identity never reaches the tracker in preflight or in task-contract capture, whether or not a Linear credential is present.
- Preflight validates a `WORK-###` identity against its repo-owned work order instead:
  - **PL1** passes only when `.ops/work/<ID>.md` is committed at HEAD and its title heading names the identity. A missing, untracked or mismatched work order fails.
  - **PL2** passes only when the work order declares `Tier:` and it equals `--tier`. The mechanical tier floor (PE2) still applies, so a declared tier below the floor fails.
  - **PL4** passes only when the work order has a non-empty `## Acceptance Criteria` section.
  - **PL5** (active-manifest conflict) and **PL6** (file-scope overlap) still run. They are not skipped.
- `UTV2-###` identities behave exactly as before: they are looked up in Linear with a credential and skipped without one. This includes the UTV2-1837 inversion, which requires that a present credential never takes the skip path.
- `fetchLinearTaskSource` refuses a `WORK-###` identity, naming the missing work order, instead of querying Linear.
- The ten untracked work orders are committed:
  - WORK-2026092606 is active, and its PM-amended contract is kept byte-for-byte.
  - The nine others are `done` on `main`, and each is the only durable record of its lane's contract, matching the six already tracked.
- Acceptance is the real Codex preflight for WORK-2026092606 passing PL1 and PG2 from the root checkout, with no Linear issue and no copied token.
