# WORK-2026092815 — Command Center: filter by distribution mode; say why a delivery-eligible pick is waiting

Tier: T2 · Lane type: delivery-ui (app: command-center) · Executor: codex

Repo-owned work order (tracker independence, ratified 2026-09-05). No Linear issue exists for this identity by design.

Required reading before any change: `docs/03_product/COMMAND_CENTER_PRODUCT_CONTRACT.md` (the sole authority for Command Center).

## Objective

Two operator gaps remain after the governed-pick truth work that merged in `617ceb93c`:

- An operator cannot list only governed Track Only or delivery-eligible picks.
- A delivery-eligible pick that is waiting behind a killed delivery target does not say why it is waiting.

**Scope:** `apps/command-center/**` only. This lane adds no API route, no write and no new table read. It may reuse the existing Command Center readers named below.

## Acceptance Criteria

Picks list (`apps/command-center/src/app/picks/page.tsx`, `apps/command-center/src/lib/picks-explorer-query.ts`, and the data reader that serves the list):

- **Filter.** Add a "Distribution mode" select to the existing filter form: `All`, `Track Only` (`track-only`), `Delivery-eligible` (`delivery-eligible`) and `Ungoverned` (no `metadata.distributionMode`).
  - `readPicksExplorerQuery` parses it into an allow-list, so an unknown value becomes `All`.
  - `picksExplorerHref` preserves it across paging.
  - The filter is applied in the existing server-side list query, not client-side on one page, so totals and paging stay correct.
  - The fixture population (`population=fixtures`) is unaffected.

Pick detail (`apps/command-center/src/app/picks/[id]/page.tsx` and `apps/command-center/src/components/GovernedPickTruth.tsx`):

- **Why it is waiting.** A pick with `distributionMode === 'delivery-eligible'` and a delivery target (for a human-capper pick, `official-picks`) shows the target's kill-switch state. Read it with the existing `getDeliveryKillSwitchStatuses()` in `apps/command-center/src/lib/data/discord-ops.ts`, following the pattern in `apps/command-center/src/app/settlement/page.tsx` around line 204.
  - When the target is killed, show "Delivery held: `official-picks` kill switch engaged", plus the stored `reason`, `actor` and `updatedAt`.
  - When the target has no row, say that delivery is held because the worker fails closed for a target with no kill-switch row.
  - When the read fails, say "Kill-switch state unavailable". It must never render as "delivery open".
  - Track Only picks do not show this block.
- **No release control.** This lane adds no button, link or form that releases a kill switch.
