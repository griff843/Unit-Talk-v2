# WORK-2026103010 — lane-start and preflight refuse malformed `--files`

Tier: T1
Lane type: governance
Executor: claude

Mechanical tier floor: T1 (`scripts/ops/lane-start.ts` is a Tier C path).

Source: Griff's operating-model directive of 2026-10-31, item 3: "Make invalid or missing CLI arguments fail clearly rather than silently admitting incomplete scope." The defect was observed on 2026-10-30, and cost one full re-admission.

## Objective

`parseArgs` in `scripts/ops/shared.ts` binds exactly one value to each `--flag`. Any further bare words become positionals.

**`ops:lane-start` and `ops:preflight` read only `positionals[0]`** (the issue ID) and ignore the rest. As a result:

- `ops:lane-start WORK-X ... --files a b c d` admitted a lane whose `file_scope_lock` was `[a]`. The other three paths were dropped without a message. The lock is pinned at lane-start and cannot be widened, so the lane had to be torn down and re-admitted with a fresh preflight (about 10 minutes, plus a control-checkout window).
- `ops:preflight ... --files a,b,c` neither splits nor refuses the value. It treats `a,b,c` as one path, and the token records a scope that does not exist.

Both CLIs should refuse these inputs with an error that names the correct form (`--files a --files b`). They must not silently admit a narrower or malformed scope.

## Acceptance Criteria

- **A pure guard in a new module, `scripts/ops/cli-args-guard.ts`**, rejects:
  - positionals beyond the expected count, naming them and the repeat-the-flag form;
  - a `--files` value containing a comma.
- **`lane-start.ts` and `preflight.ts` call the guard** immediately after argument parsing, before any lease, worktree, manifest, Linear call or baseline run.
- **Correct invocations are unaffected.** A single issue positional with repeated `--files` behaves exactly as before.
- **Unit tests in the already-registered `scripts/ops/lane-start.test.ts`** cover:
  - extra positionals refused;
  - a comma-joined path refused;
  - repeated flags and a single positional accepted;
  - an empty `--files` list left to the existing checks.
- **Mutation evidence:** disabling each rule fails a test.

## File Scope

- `scripts/ops/cli-args-guard.ts`
- `scripts/ops/lane-start.ts`
- `scripts/ops/lane-start.test.ts`
- `scripts/ops/preflight.ts`
- `.ops/work/WORK-2026103010.md`

## Out of Scope

- `scripts/ops/shared.ts` and `shared.test.ts`. Both are locked by the open UTV2-1977 lane (#1739), so the guard lives in its own module instead.

- Changing `parseArgs` itself or any of its other ~57 consumers.
- Unknown-flag rejection. That needs a per-CLI allowlist and is a larger change.
- Splitting comma-joined values. Refusing is the conservative choice, and adding a second accepted syntax is a separate decision.
- Any change to tiering, the merge gate, lane policy or admission rules.

## Rollback

Revert the PR. The guard only refuses inputs that were already wrong.
